MITIGATION MODEL — can K be removed?
Short answer: no. Every workable mitigation model needs a constant of this kind — the real question is its value, not its existence.

Subtractive (ATK − DEF) zeroes out. Across the game's real stat ranges, 7 of 24 attacker/defender pairs deal zero or negative damage — a LV1 attacker literally cannot scratch a LV20 defender, so progress stops rather than slows.

Pure ratio (ATK ÷ DEF) is unbounded as DEF falls. At ATK 66 vs DEF 8 it deals 165 against the current model's 50 — low-DEF enemies get one-shot and the curve has no floor to tune against.

Percentage reduction with another constant is the same formula wearing a different name. K=10, K=25 and K=60 are one family; only the steepness changes.

So the honest framing: K is not a level mechanic. Its level scaling (23 + 2×level) is dead code, because level is always 1. It is a single tuning knob for how much DEF matters, and the only live questions are what value it takes and whether it should scale with depth.
WHERE THE CODE DIVERGES FROM GDD §3
1. K is a constant 25. K_of(l)=23+2*l, but makeUnit is called with level:1 everywhere and level is never incremented — v1.0 moved growth into per-unit stat curves. Mitigation does not soften as you level, whatever the doc says.

2. Enrage is not a step in this chain. It mutates the attacker's base ATK after that unit acts, so it compounds into effective offence on later turns rather than multiplying damage. It looks like a damage step and isn't.

3. Evade is physical-only. §3.3 lists it as step 1 without that qualification. Magic cannot miss.

4. Crit, block and evade are fully symmetric — resolveHit has no isParty check. The only party-only terms are the three row modifiers.
